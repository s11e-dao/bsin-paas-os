## 1. 系统概述

事件积分奖励系统是一个基于用户行为事件触发的资产奖励机制，支持多租户、多种资产类型（积分、金币、经验值等）的灵活配置和自动发放。

### 1.1 设计目标

- **简洁性**：采用极简设计，仅使用两张核心表完成功能
- **灵活性**：通过JSON配置支持复杂的奖励规则
- **扩展性**：支持多种事件类型和奖励模式
- **高效性**：基于事件驱动，实时响应用户行为

### 1.2 核心特性

- 🎯 事件驱动的奖励机制
- 🏢 多租户数据隔离
- 🔧 灵活的JSON配置
- 📊 多维度的奖励统计
- ⚡ 高性能异步处理

## 2. 系统架构

### 2.1 整体架构

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   业务系统      │────│  事件奖励系统   │────│   资产系统      │
│                 │    │                 │    │                 │
│ - 用户行为触发  │    │ - 事件处理      │    │ - 积分发放      │
│ - 订单事件      │    │ - 规则匹配      │    │ - 余额更新      │
│ - 系统事件      │    │ - 奖励计算      │    │ - 记录日志      │
└─────────────────┘    └─────────────────┘    └─────────────────┘
```

### 2.2 核心表结构

系统主要由两张表组成：

#### 2.2.1 事件表（brms_event）

存储系统中所有可触发奖励的事件定义。

| 字段名      | 类型         | 说明                                        |
|-------------|--------------|---------------------------------------------|
| serial_no   | varchar(32)  | 主键，事件唯一标识                          |
| tenant_id   | varchar(64)  | 租户ID，支持多租户                          |
| event_name  | varchar(64)  | 事件名称                                    |
| event_code  | varchar(32)  | 事件编码，业务系统调用标识                  |
| event_level | varchar(255) | 事件级别：1-平台级 2-商户级                 |
| event_type  | varchar(32)  | 事件类型：USER-用户事件 ORDER-订单事件 SYSTEM-系统事件 |

#### 2.2.2 事件模型表（brms_event_model）

存储事件对应的奖励规则配置，核心是model_config JSON字段。

| 字段名       | 类型         | 说明                           |
|--------------|--------------|--------------------------------|
| serial_no    | varchar(32)  | 主键，模型唯一标识             |
| event_code   | varchar(255) | 关联事件编码                   |
| model_type   | varchar(255) | 模型类型：3-规则模型（奖励规则）|
| model_config | json         | 规则配置（JSON格式）           |
| priority     | int(11)      | 优先级，支持同一事件多个规则   |

### 2.3 JSON配置结构

`model_config` 字段采用JSON格式存储复杂的奖励规则：

```json
{
  "rewards": [
    {
      "assetType": "POINTS",
      "amountType": "FIXED|RANDOM|FORMULA|PERCENT",
      "amount": 10,
      "minAmount": 5,
      "maxAmount": 20,
      "formula": "days * 5",
      "description": "奖励描述"
    }
  ],
  "conditions": [
    {
      "field": "orderAmount",
      "operator": "gte",
      "value": 100,
      "description": "订单金额>=100"
    }
  ],
  "limits": {
    "dailyLimit": 1,
    "totalLimit": 0
  },
  "effectTime": {
    "startTime": null,
    "endTime": null
  }
}
```
## 3. 功能特性

### 3.1 多样化奖励类型

#### 3.1.1 固定奖励（FIXED）
- **机制**：每次触发给予固定数量的奖励
- **适用场景**：登录奖励、签到奖励等
- **配置示例**：
  ```json
  {
    "assetType": "POINTS",
    "amountType": "FIXED",
    "amount": 10
  }
  ```

#### 3.1.2 随机奖励（RANDOM）
- **机制**：在指定区间内随机给予奖励
- **适用场景**：分享奖励、抽奖活动等
- **配置示例**：
  ```json
  {
    "assetType": "POINTS",
    "amountType": "RANDOM",
    "minAmount": 5,
    "maxAmount": 20
  }
  ```

#### 3.1.3 公式计算（FORMULA）
- **机制**：支持动态公式计算奖励数量
- **适用场景**：连续签到递增、VIP等级奖励等
- **配置示例**：
  ```json
  {
    "assetType": "POINTS",
    "amountType": "FORMULA",
    "formula": "days * 5"
  }
  ```

#### 3.1.4 比例奖励（PERCENT）
- **机制**：按照事件数据的某个值按比例给予奖励
- **适用场景**：订单返佣、消费积分等
- **配置示例**：
  ```json
  {
    "assetType": "POINTS",
    "amountType": "PERCENT",
    "amount": 1,
    "field": "orderAmount"
  }
  ```

### 3.2 灵活的触发条件

支持多种条件判断操作符：

| 操作符 | 说明       | 示例                    |
|--------|------------|-------------------------|
| eq     | 等于       | `"operator": "eq"`      |
| ne     | 不等于     | `"operator": "ne"`      |
| gt     | 大于       | `"operator": "gt"`      |
| gte    | 大于等于   | `"operator": "gte"`     |
| lt     | 小于       | `"operator": "lt"`      |
| lte    | 小于等于   | `"operator": "lte"`     |
| in     | 包含       | `"operator": "in"`      |
| like   | 模糊匹配   | `"operator": "like"`    |

### 3.3 完善的限制机制

- **每日限制**：防止单日过度获取
- **总次数限制**：控制活动总量
- **时间限制**：活动有效期控制
- **优先级排序**：多规则执行顺序

### 3.4 多租户支持

- **数据隔离**：基于tenant_id实现数据隔离
- **独立配置**：支持不同租户独立配置规则
- **SaaS化**：便于SaaS化部署

## 4. 典型应用场景

### 4.1 用户行为激励

| 事件        | 奖励规则        | 限制条件           |
|-------------|----------------|--------------------|
| 每日登录    | 固定10积分      | 每日1次            |
| 分享内容    | 5-20积分随机    | 每日3次            |
| 连续签到    | 天数×5积分      | 每日1次，最高7天   |
| 完善资料    | 固定50积分      | 总共1次            |

**配置示例 - 每日登录奖励**：
```json
{
  "rewards": [
    {
      "assetType": "POINTS",
      "amountType": "FIXED",
      "amount": 10,
      "description": "每日登录积分奖励"
    }
  ],
  "limits": {
    "dailyLimit": 1,
    "totalLimit": 0
  }
}
```

### 4.2 交易激励

| 事件        | 奖励规则           | 触发条件           |
|-------------|-------------------|--------------------|
| 首次下单    | 固定100积分        | 用户首单           |
| 完成订单    | 订单金额1%积分     | 金额≥100元         |
| 好评晒图    | 固定30积分         | 订单已完成         |

**配置示例 - 订单返积分**：
```json
{
  "rewards": [
    {
      "assetType": "POINTS",
      "amountType": "PERCENT",
      "amount": 1,
      "field": "orderAmount",
      "description": "订单返积分"
    }
  ],
  "conditions": [
    {
      "field": "orderAmount",
      "operator": "gte",
      "value": 100,
      "description": "订单金额≥100元"
    }
  ]
}
```

### 4.3 社交互动

| 事件        | 奖励规则           | 限制条件           |
|-------------|-------------------|--------------------|
| 邀请好友    | 固定200积分        | 好友成功注册       |
| 好友下单    | 订单金额2%积分     | 被邀请好友首单     |
| 发布动态    | 10-50积分随机      | 每日5次            |

**配置示例 - 邀请好友奖励**：
```json
{
  "rewards": [
    {
      "assetType": "POINTS",
      "amountType": "FIXED",
      "amount": 200,
      "description": "邀请好友注册奖励"
    }
  ],
  "conditions": [
    {
      "field": "inviteStatus",
      "operator": "eq",
      "value": "SUCCESS",
      "description": "好友成功注册"
    }
  ]
}
```
## 5. 系统优势

### 5.1 简单易维护
- ✅ **极简设计**：仅两张表，结构清晰
- ✅ **配置直观**：JSON配置易于理解和修改
- ✅ **高性能**：减少表关联，提高查询性能

### 5.2 配置灵活性
- 🔧 **复杂逻辑**：支持复杂的奖励计算逻辑
- 🔧 **条件组合**：多条件组合判断
- 🔧 **动态计算**：支持公式动态计算

### 5.3 业务扩展性
- 🚀 **无缝扩展**：新增事件类型无需修改表结构
- 🚀 **在线配置**：奖励规则可在线配置
- 🚀 **灰度支持**：支持A/B测试和灰度发布

### 5.4 数据完整性
- 📊 **全程追溯**：所有奖励操作可追溯
- 📊 **统计分析**：支持数据统计分析
- 📊 **审计友好**：便于对账和审计

## 6. 实现建议

### 6.1 性能优化
```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   事件缓存      │    │   规则缓存      │    │   异步队列      │
│                 │    │                 │    │                 │
│ - Redis缓存     │    │ - 热点规则      │    │ - 奖励发放      │
│ - 防重复提交    │    │ - 定期刷新      │    │ - 批量处理      │
└─────────────────┘    └─────────────────┘    └─────────────────┘
```

#### 关键措施：
- **缓存机制**：对高频事件添加Redis缓存
- **异步处理**：奖励发放采用消息队列异步处理
- **索引优化**：在tenant_id、event_code等字段建立索引

### 6.2 安全考虑

#### 防护措施：
- **防重复**：基于事件ID + 用户ID + 时间戳防重复提交
- **限额保护**：设置单次、单日、总量奖励上限
- **异常处理**：完善的事务回滚和补偿机制

### 6.3 监控告警

#### 监控指标：
- **成功率监控**：奖励发放成功率 > 99.9%
- **异常告警**：单用户异常获取、规则异常等
- **业务统计**：奖励发放量、用户参与度等

## 9. 总结

本设计通过极简的两表结构，结合灵活的JSON配置，实现了功能完备的事件积分奖励系统。系统具备以下核心优势：

- ⚡ **高性能**：基于事件驱动，支持高并发处理
- 🎯 **高灵活**：JSON配置支持复杂业务规则
- 🔧 **易维护**：简洁架构，开发和运维成本低
- 📈 **可扩展**：支持多租户，便于业务扩展

该方案特别适合中小型项目快速上线，同时具备良好的扩展能力支持业务长期发展。通过合理的架构设计和实现策略，能够有效提升用户活跃度和业务转化率。
