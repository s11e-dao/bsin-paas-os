## 模块概览

### 系统定位
本地生活服务平台的**全员分销营销系统**，实现客户、合伙人、商户三方共赢的生态体系。

### 核心特色
- **全员分销**：每个注册客户自动成为分销员
- **区域化管理**：合伙人按地理区域管理商户
- **智能分佣**：基于业态、地理位置、等级的多维度分佣
- **等级体系**：统一的多角色等级管理系统

### 技术架构
```
前端应用
    ↓
API网关(Shenyu)
    ↓
Dubbo服务层（8个核心Service）
    ↓
数据持久层（MyBatis Plus + MySQL）
    ↓
缓存层（Redis）+ 消息队列（RabbitMQ）
```

## 核心数据结构

### 1. 等级体系（crm_grade）
**设计亮点**：统一等级表支持多角色

```
核心字段：
├── serial_no              # 等级唯一标识
├── biz_role_type          # 角色类型（DISTRIBUTOR/AGENT_*/MERCHANT）
├── grade_num              # 等级序号（1-4）
├── commission_rate        # 该等级默认分佣比例
├── upgrade_invite_count   # 升级所需邀请人数
├── upgrade_commission     # 升级所需分佣金额
└── level_privileges       # 等级特权（JSON格式）

支持角色：
├── DISTRIBUTOR           # 分销员（4级）
├── AGENT_PROVINCE        # 省级合伙人（4级）
├── AGENT_CITY            # 市级合伙人（4级）
├── AGENT_COUNTY          # 县级合伙人（4级）
├── AGENT_DISTRICT        # 区级合伙人（4级）
├── AGENT_TOWN            # 镇级合伙人（4级）
└── MERCHANT              # 商户（4级）
```

### 2. 邀请关系（crm_dis_invite_relation）
**功能**：追踪客户推广关系链

```
核心字段：
├── customer_no            # 被邀请人客户编号
├── parent_no              # 邀请人客户编号
├── invite_level           # 邀请层级（1-N）
└── create_time            # 邀请时间

关系链示例：
A邀请B → B邀请C → C邀请D
├── B的parent_no = A
├── C的parent_no = B
└── D的parent_no = C
```

### 3. 团队关系（crm_dis_team_relation）
**功能**：管理合伙人团队层级和动态调整

```
核心字段：
├── sys_agent_no           # 合伙人编号
├── prarent_sys_agent_no   # 上级合伙人编号
├── dis_agent_type         # 角色类型（BOSS/DISTRIBUTOR）
├── tenant_id              # 租户ID
└── merchant_no            # 商户编号（可选）

角色类型：
├── BOSS                   # 老板合伙人（团队创建者）
└── DISTRIBUTOR            # 分销合伙人（团队成员）
```

### 4. 分销模型配置（crm_dis_model）
**功能**：定义分销模式和规则

```
核心字段：
├── model                  # 分销模型（DIS_LEVEL21等）
├── quit_current_limit     # 走人阈值（链动2+1模式）
├── tenant_id              # 租户ID
└── merchant_no            # 商户编号（可选）

支持模型：
├── DIS_LEVEL21            # 链动2+1模型
├── DIS_TRADITIONAL        # 传统层级模型
└── DIS_FLAT               # 扁平化模型
```

### 5. 分佣流水（crm_dis_commission_journal）
**功能**：记录每笔分佣明细

```
核心字段：
├── customer_no            # 获得分佣的客户编号
├── inviter_customer_no    # 邀请人客户编号
├── commission_amount      # 分佣金额
├── commission_type        # 分佣类型（ORDER/INVITE）
├── region_code            # 区域编码
├── settlement_status      # 结算状态
└── settlement_time        # 结算时间
```

### 模块3：团队关系管理（DisTeamRelationServiceImpl）⭐

#### 功能职责
这是**最核心**的模块，负责：
- 合伙人团队的组建
- 实现链动2+1的"走人留人"机制
- 动态调整团队层级关系

#### 核心流程：用户成为合伙人

```
add(requestMap) 处理流程：

输入参数：
├── customerNo          # 新合伙人的客户ID
├── sysAgentNo          # 合伙人记录ID
├── tenantId            # 租户ID
└── merchantNo          # 商户ID（可选）

第一步：查询分销模型配置
├── 查询条件：tenantId + merchantNo
├── 校验：模型配置必须存在
└── 获取：quitCurrentLimit（走人阈值）

第二步：查询合伙人信息
├── 根据sysAgentNo查询
└── 校验：合伙人记录必须存在

第三步：查询邀请关系
├── 根据customerNo查询邀请关系
└── 判断：是否有上级邀请人

第四步：判断组队方式

【情况A】无邀请关系：
    ├── 设置角色：BOSS（老板合伙人）
    ├── 创建团队：独立团队
    └── 返回结果

【情况B】有邀请关系，但邀请人不是合伙人：
    ├── 查询邀请人身份
    ├── 判断：邀请人无合伙人身份
    ├── 设置角色：BOSS（老板合伙人）
    └── 创建独立团队

【情况C】有邀请关系，且邀请人是合伙人：
    ├── 加入邀请人团队
    ├── 设置上级：prarentSysAgentNo = 邀请人合伙人ID
    ├── 设置角色：DISTRIBUTOR（分销合伙人）
    └── 继续第五步

第五步：链动2+1逻辑处理

IF 分销模型 == "DIS_LEVEL21" AND 邀请人不是BOSS：
    ├── 查询邀请人的直推人数
    │
    IF 直推人数 >= quitCurrentLimit：
        ├── 【走人逻辑】
        ├── 1. 邀请人的所有下级 → 转移给邀请人的上级
        ├── 2. 邀请人角色变更为BOSS
        ├── 3. 邀请人退出原团队（prarentSysAgentNo = "-1"）
        └── 4. 更新所有相关记录
    ELSE：
        └── 保持现有团队关系

返回：团队关系记录
```

#### 链动2+1核心机制

**设计理念**：达到一定直推人数后，合伙人"晋升"为老板并退出原团队

```
假设quitCurrentLimit = 2：

初始状态：
老板A
 └── 合伙人B（已有1个下级）

B邀请C成为合伙人：
├── C加入B的团队
├── B的直推人数 = 2
└── 触发走人机制

执行走人：
├── B的下级（包括C）→ 转移给A
├── B变成老板
└── B退出原团队

最终状态：
老板A                老板B（新）
 ├── C
 └── （B原来的其他下级）
```

#### 数据变更示例

```sql
-- 走人前
crm_dis_team_relation:
├── B: {prarent_sys_agent_no: A, dis_agent_type: DISTRIBUTOR}
├── C: {prarent_sys_agent_no: B, dis_agent_type: DISTRIBUTOR}

-- 走人后
crm_dis_team_relation:
├── B: {prarent_sys_agent_no: "-1", dis_agent_type: BOSS}
├── C: {prarent_sys_agent_no: A, dis_agent_type: DISTRIBUTOR}
```

## 关键业务流程

### 流程1：新用户注册并成为分销员

```
用户注册流程：

1. 客户端提交注册信息
   ├── 手机号/邮箱
   ├── 密码
   └── 邀请码（可选）

2. 系统创建客户记录
   ├── crm_customer_base.insert()
   ├── 生成customer_no
   ├── 生成invite_code（专属邀请码）
   └── 初始化等级：grade_no = 'DIST_001'（初级分销员）

3. 创建等级关系记录
   ├── crm_customer_grade.insert()
   ├── customer_no 关联客户
   ├── grade_no = 'DIST_001'
   └── is_active = 1

4. 如果有邀请码，建立邀请关系
   ├── 查询邀请人：WHERE invite_code = inputInviteCode
   ├── crm_dis_invite_relation.insert()
   ├── customer_no = 新用户ID
   ├── parent_no = 邀请人ID
   └── invite_level = 1

5. 返回注册成功
   └── 用户自动成为分销员身份
```

### 流程2：客户升级为合伙人

```
升级合伙人流程：

1. 客户申请成为合伙人
   ├── 提交申请资料
   ├── 选择管辖区域
   └── 等待审核

2. 平台审核通过
   ├── 创建合伙人记录：crm_sys_agent.insert()
   ├── 创建身份记录：crm_customer_identity.insert()
   │   ├── biz_role_type = 'SYS_AGENT'
   │   └── biz_role_type_no = agent_no
   └── 初始化等级：grade_no = 'TOWN_AGENT_L1'

3. 创建合伙人等级关系
   ├── crm_agent_grade.insert()
   ├── agent_no 关联合伙人
   └── grade_no = 'TOWN_AGENT_L1'

4. 调用团队关系模块
   ├── DisTeamRelationService.add()
   ├── 传入：customerNo, sysAgentNo, tenantId
   └── 执行团队组建逻辑（详见模块3）

5. 返回合伙人信息
   └── 包含团队关系和等级信息
```

### 流程3：订单分佣计算

```
订单完成分佣流程：

1. 订单状态变更为"已完成"
   └── 触发分佣计算事件

2. 查询订单相关信息
   ├── 下单客户：customer_no
   ├── 商户信息：merchant_no
   ├── 订单金额：order_amount
   └── 区域信息：region_code

3. 查询客户邀请关系链
   ├── SELECT * FROM crm_dis_invite_relation
   ├── WHERE customer_no = 下单客户
   └── 递归查询上级关系（多层）

4. 查询商户分佣政策
   ├── 查询商户关联的政策
   ├── 查询政策下的分佣规则
   └── 获取分佣比例配置

5. 查询商户管理合伙人
   ├── SELECT agent_no FROM crm_merchant
   ├── 查询合伙人等级信息
   └── 获取合伙人分佣比例

6. 执行分佣计算
   ├── 计算客户分佣（基于邀请关系）
   │   ├── 一级邀请人分佣
   │   └── 二级邀请人分佣
   │
   └── 计算合伙人分佣
       ├── 商户管理合伙人
       └── 上级合伙人（如果有）

7. 记录分佣流水
   ├── crm_dis_commission_journal.insert()（多条）
   ├── 每个获得分佣的人一条记录
   └── 包含：金额、类型、来源、状态

8. 更新统计字段
   ├── 更新客户分佣统计
   │   ├── total_commission += 分佣金额
   │   └── current_commission += 分佣金额
   │
   └── 更新合伙人分佣统计
       ├── total_commission += 分佣金额
       └── monthly_commission += 分佣金额

9. 检查等级升级
   ├── 判断是否满足升级条件
   ├── 计算升级进度
   └── 如果满足，执行升级

10. 发送分佣通知
    └── 通知各方分佣到账
```

### 流程4：等级升级检查

```
等级升级流程：

1. 触发条件
   ├── 分佣金额变化
   ├── 邀请人数变化
   └── 定时任务检查

2. 查询当前等级
   ├── 客户：查询 crm_customer_grade（is_active=1）
   └── 合伙人：查询 crm_agent_grade（is_active=1）

3. 查询下一等级条件
   ├── 当前等级：grade_num = N
   ├── 下一等级：grade_num = N+1
   └── 相同 biz_role_type

4. 获取升级条件
   ├── upgrade_invite_count    # 所需邀请人数
   └── upgrade_commission      # 所需分佣金额

5. 判断是否满足条件
   IF (current_invite_count >= upgrade_invite_count 
       OR current_commission >= upgrade_commission) {
       
       执行升级：
       ├── 旧等级关系：is_active = 0
       ├── 创建新等级关系：is_active = 1
       ├── 更新last_upgrade_time
       └── 重置升级进度

   } ELSE {
       
       计算升级进度：
       ├── 邀请进度 = current_invite_count / upgrade_invite_count * 100
       ├── 分佣进度 = current_commission / upgrade_commission * 100
       └── 总进度 = MAX(邀请进度, 分佣进度)
   }

6. 返回升级结果
   └── 包含：是否升级、新等级、升级进度
```

## 核心算法设计

### 算法1：链动2+1走人留人算法

**算法名称**：动态团队重组算法（DTR - Dynamic Team Restructuring）

**输入参数**：
- newAgentNo: 新加入合伙人ID
- parentAgentNo: 邀请人合伙人ID
- quitLimit: 走人阈值

**算法步骤**：

```
FUNCTION addToTeam(newAgentNo, parentAgentNo, quitLimit):

    // 步骤1：查询邀请人当前状态
    parentTeam = SELECT * FROM crm_dis_team_relation
                 WHERE sys_agent_no = parentAgentNo
    
    // 步骤2：新合伙人加入团队
    newTeam = {
        sys_agent_no: newAgentNo,
        prarent_sys_agent_no: parentAgentNo,
        dis_agent_type: 'DISTRIBUTOR'
    }
    INSERT INTO crm_dis_team_relation VALUES newTeam
    
    // 步骤3：检查走人条件
    IF parentTeam.dis_agent_type != 'BOSS':
        
        // 统计邀请人的直推人数
        childCount = SELECT COUNT(*) 
                     FROM crm_dis_team_relation
                     WHERE prarent_sys_agent_no = parentAgentNo
        
        // 步骤4：判断是否触发走人
        IF childCount >= quitLimit:
            
            // 步骤5：执行走人逻辑
            
            // 5.1 找到邀请人的上级
            grandParentNo = parentTeam.prarent_sys_agent_no
            
            // 5.2 邀请人的所有下级转移给上级
            UPDATE crm_dis_team_relation
            SET prarent_sys_agent_no = grandParentNo
            WHERE prarent_sys_agent_no = parentAgentNo
            
            // 5.3 邀请人晋升为老板
            UPDATE crm_dis_team_relation
            SET dis_agent_type = 'BOSS',
                prarent_sys_agent_no = '-1'
            WHERE sys_agent_no = parentAgentNo
            
            RETURN {
                status: 'QUIT_TRIGGERED',
                promotedBoss: parentAgentNo,
                transferredCount: childCount
            }
        
        END IF
    END IF
    
    RETURN {
        status: 'JOINED',
        teamLeader: parentAgentNo
    }

END FUNCTION
```

**算法复杂度**：
- 时间复杂度：O(N)，N为邀请人的直推人数
- 空间复杂度：O(1)

**算法特点**：

### 算法2：多维度分佣计算算法

**算法名称**：智能分佣引擎（ICE - Intelligent Commission Engine）

**输入参数**：
- order: 订单对象
- businessType: 商户业态
- inviteChain: 邀请关系链
- agentChain: 合伙人关系链

**算法步骤**：

```
FUNCTION calculateCommission(order, businessType, inviteChain, agentChain):

    commissionList = []
    
    // ========== 第一部分：客户邀请分佣 ==========
    
    // 获取业态基础分佣比例
    baseRate = businessType.commission_rate  // 例如：0.08（8%）
    
    // 热门业态加成
    IF businessType.is_hot == 1:
        baseRate = baseRate * 1.2
    END IF
    
    // 遍历邀请关系链（通常2级）
    FOR level = 1 TO inviteChain.length:
        
        inviter = inviteChain[level]
        
        // 查询邀请人等级信息
        customerGrade = SELECT cg.*, g.commission_rate, g.grade_num
                        FROM crm_customer_grade cg
                        JOIN crm_grade g ON cg.grade_no = g.serial_no
                        WHERE cg.customer_no = inviter.customer_no
                        AND cg.is_active = 1
        
        // 等级系数
        levelFactor = CASE customerGrade.grade_num
            WHEN '4': 1.3  // 金牌
            WHEN '3': 1.2  // 高级
            WHEN '2': 1.1  // 中级
            ELSE: 1.0      // 初级
        END CASE
        
        // 层级衰减（一级100%，二级60%）
        tierDiscount = level == 1 ? 1.0 : 0.6
        
        // 计算该级分佣
        commission = order.amount * baseRate * levelFactor * tierDiscount
        
        commissionList.ADD({
            recipient: inviter.customer_no,
            type: 'CUSTOMER_INVITE',
            level: level,
            amount: commission,
            rate: baseRate * levelFactor * tierDiscount
        })
    
    END FOR
    
    // ========== 第二部分：合伙人管理分佣 ==========
    
    // 查询商户的管理合伙人
    merchant = SELECT * FROM crm_merchant 
               WHERE merchant_no = order.merchant_no
    
    IF merchant.agent_no IS NOT NULL:
        
        // 查询合伙人等级
        agentGrade = SELECT ag.*, g.commission_rate, g.grade_num
                     FROM crm_agent_grade ag
                     JOIN crm_grade g ON ag.grade_no = g.serial_no
                     WHERE ag.agent_no = merchant.agent_no
                     AND ag.is_active = 1
        
        // 直接管理合伙人分佣（使用等级配置的分佣比例）
        agentCommission = order.amount * agentGrade.commission_rate
        
        commissionList.ADD({
            recipient: merchant.agent_no,
            type: 'AGENT_MANAGE',
            level: 1,
            amount: agentCommission,
            rate: agentGrade.commission_rate
        })
        
        // ========== 第三部分：上级合伙人分佣 ==========
        
        // 查询合伙人的团队关系
        agentTeam = SELECT * FROM crm_dis_team_relation
                    WHERE sys_agent_no = merchant.agent_no
        
        IF agentTeam.prarent_sys_agent_no != '-1':
            
            parentAgent = agentTeam.prarent_sys_agent_no
            
            // 查询上级合伙人等级
            parentGrade = SELECT ag.*, g.commission_rate, g.grade_num
                          FROM crm_agent_grade ag
                          JOIN crm_grade g ON ag.grade_no = g.serial_no
                          WHERE ag.agent_no = parentAgent
                          AND ag.is_active = 1
            
            // 上级获得差额分佣（上级分佣率 - 下级分佣率）
            rateDiff = parentGrade.commission_rate - agentGrade.commission_rate
            
            IF rateDiff > 0:
                parentCommission = order.amount * rateDiff
                
                commissionList.ADD({
                    recipient: parentAgent,
                    type: 'AGENT_PARENT',
                    level: 2,
                    amount: parentCommission,
                    rate: rateDiff
                })
            END IF
        
        END IF
    
    END IF
    
    // ========== 返回结果 ==========
    
    RETURN {
        total: SUM(commissionList.amount),
        details: commissionList,
        orderNo: order.order_no,
        calculateTime: NOW()
    }

END FUNCTION
```

**算法特点**：
1. **多维度**：客户等级、合伙人等级、业态类型
2. **公平性**：差额分佣机制保证公平
3. **灵活性**：支持配置化调整
4. **完整性**：覆盖所有分佣场景

### 算法3：等级升级进度计算算法

**算法名称**：智能升级跟踪算法（SUT - Smart Upgrade Tracking）

**输入参数**：
- currentGradeNo: 当前等级ID
- roleType: 角色类型（DISTRIBUTOR/AGENT_*）
- currentStats: 当前统计数据

**算法步骤**：

```
FUNCTION calculateUpgradeProgress(currentGradeNo, roleType, currentStats):

    // 步骤1：查询当前等级信息
    currentGrade = SELECT * FROM crm_grade
                   WHERE serial_no = currentGradeNo
    
    // 步骤2：查询下一等级
    nextGrade = SELECT * FROM crm_grade
                WHERE biz_role_type = roleType
                AND grade_num = currentGrade.grade_num + 1
                ORDER BY grade_num ASC
                LIMIT 1
    
    // 如果已是最高等级
    IF nextGrade IS NULL:
        RETURN {
            isMaxLevel: true,
            progress: 100.0,
            nextGrade: null,
            canUpgrade: false
        }
    END IF
    
    // 步骤3：计算各维度进度
    
    // 3.1 邀请人数进度
    IF nextGrade.upgrade_invite_count > 0:
        inviteProgress = (currentStats.invite_count / nextGrade.upgrade_invite_count) * 100
    ELSE:
        inviteProgress = 100.0
    END IF
    
    // 3.2 分佣金额进度
    IF nextGrade.upgrade_commission > 0:
        commissionProgress = (currentStats.commission / nextGrade.upgrade_commission) * 100
    ELSE:
        commissionProgress = 100.0
    END IF
    
    // 步骤4：综合进度计算
    // 采用"或"逻辑：任一条件满足即可升级
    overallProgress = MAX(inviteProgress, commissionProgress)
    
    // 限制最大值为100
    IF overallProgress > 100:
        overallProgress = 100.0
    END IF
    
    // 步骤5：判断是否可升级
    canUpgrade = (inviteProgress >= 100.0) OR (commissionProgress >= 100.0)
    
    // 步骤6：返回结果
    RETURN {
        isMaxLevel: false,
        progress: overallProgress,
        inviteProgress: inviteProgress,
        commissionProgress: commissionProgress,
        nextGrade: {
            gradeNo: nextGrade.serial_no,
            gradeName: nextGrade.name,
            gradeNum: nextGrade.grade_num,
            requiredInvites: nextGrade.upgrade_invite_count,
            requiredCommission: nextGrade.upgrade_commission,
            privileges: nextGrade.level_privileges
        },
        currentStats: {
            invites: currentStats.invite_count,
            commission: currentStats.commission
        },
        canUpgrade: canUpgrade,
        gapInfo: {
            invitesNeeded: MAX(0, nextGrade.upgrade_invite_count - currentStats.invite_count),
            commissionNeeded: MAX(0, nextGrade.upgrade_commission - currentStats.commission)
        }
    }

END FUNCTION
```

**算法复杂度**：
- 时间复杂度：O(1)
- 空间复杂度：O(1)

**算法特点**：
1. **实时性**：随时可查询升级进度
2. **透明性**：清晰展示升级条件和差距
3. **激励性**：可视化进度激励用户
4. **灵活性**：支持多维度升级条件
