# 等级规则配置系统设计方案

## 一、项目概述

### 1.1 项目背景
为了提升用户活跃度和粘性，需要构建一套灵活的等级体系，支持会员等级、分销等级、商户等级等多种业务角色的等级管理。系统需要支持基于Web3资产（NFT、Token等）和传统业务指标的等级晋升规则配置。

### 1.2 设计目标
- **通用性**：支持多种业务角色类型的等级配置
- **灵活性**：支持复杂的多维度条件组合
- **扩展性**：便于新增等级类型和条件维度
- **自动化**：支持自动晋升/降级机制
- **可追溯**：完整记录等级变更历史

### 1.3 适用场景
- 电商平台的会员等级体系
- 分销系统的代理等级管理
- SaaS平台的商户分级
- Web3项目的用户等级（基于NFT/Token持有）
- 社交平台的用户成长体系

### 2.2 核心模块

#### 2.2.1 配置管理模块
- 等级配置：定义各角色类型的等级层级
- 规则配置：设置等级晋升/降级规则
- 条件配置：定义具体的判定条件
- 权益配置：配置各等级的权益内容

#### 2.2.2 等级判定模块
- 条件计算：根据用户数据计算各维度指标
- 规则匹配：匹配符合条件的最高等级
- 等级变更：执行等级晋升/降级操作
- 日志记录：记录变更详情

#### 2.2.3 定时任务模块
- 自动检查：定期扫描用户等级
- 批量晋升：批量处理符合条件的用户
- 过期处理：处理等级过期用户
- 数据统计：生成等级分布报表

## 三、数据库设计

### 3.1 核心表结构

#### 3.1.1 等级配置表（crm_grade）

|------|------|------|
| serial_no | VARCHAR(32) | 主键序列号 |
| tenant_id | VARCHAR(32) | 租户ID |
| merchant_no | VARCHAR(32) | 商户编号 |
| biz_role_type | VARCHAR(50) | 业务角色类型 |

## 四、核心业务流程

### 4.1 等级晋升流程

```
用户触发事件（资产变化/行为发生）
    ↓
获取用户当前等级
    ↓
查询该角色类型的所有等级配置
    ↓
按 grade_num 从高到低遍历
    ↓
查询该等级的晋升规则
    ↓
获取规则关联的所有条件
    ↓
根据 rule_type 判断：
    ├─ AND：所有条件都满足 → 晋升
    └─ OR：任一条件满足 → 晋升
    ↓
更新 crm_biz_role_grade
    ↓
写入 crm_grade_change_log
    ↓
触发等级变更事件（发送通知、更新权益）
```

### 4.2 条件判定流程

```
获取条件配置
    ↓
判断条件类型：
    ├─ Web3资产类型（1-8）
    │   ↓
    │   查询用户钱包资产
    │   ↓
    │   根据 type_protocol 获取资产余额
    │   ↓
    │   与 value 阈值比较
    │
    └─ 传统维度类型（9）
        ↓
        查询用户业务数据
        ↓
        计算维度指标值
        ↓
        与 value 阈值比较
    ↓
返回判定结果（true/false）
```

### 4.3 自动检查流程

```
定时任务触发（每小时/每天）
    ↓
查询 next_check_time <= NOW() 的用户
    ↓
批量获取用户数据
    ↓
逐个执行等级判定
    ↓
符合晋升条件 → 执行晋升
    ↓
符合降级条件 → 执行降级
    ↓
更新 next_check_time
    ↓
生成处理报告
```

## 六、技术实现要点

### 6.1 等级判定引擎

```java
public class GradeEvaluationEngine {
    
    /**
     * 评估用户等级
     */
    public GradeEvaluationResult evaluate(String userId, String roleType) {
        // 1. 获取用户当前等级
        UserGrade currentGrade = getUserGrade(userId, roleType);
        
        // 2. 获取该角色类型的所有等级（按grade_num降序）
        List<Grade> allGrades = getGradesOrderByNum(roleType);
        
        // 3. 从最高等级开始判断
        for (Grade grade : allGrades) {
            if (grade.getGradeNum() <= currentGrade.getGradeNum()) {
                continue; // 跳过当前等级及以下
            }
            
            // 4. 检查该等级的晋升规则
            if (checkGradeRules(userId, grade)) {
                return new GradeEvaluationResult(true, grade);
            }
        }
        
        return new GradeEvaluationResult(false, currentGrade);
    }
    
    /**
     * 检查等级规则
     */
    private boolean checkGradeRules(String userId, Grade grade) {
        // 获取该等级的所有规则
        List<ConditionRelation> relations = getConditionRelations(grade.getSerialNo());
        
        // 按 rule_type 分组
        Map<String, List<ConditionRelation>> groupedRelations = 
            relations.stream().collect(Collectors.groupingBy(ConditionRelation::getRuleType));
        
        // AND规则：所有条件都必须满足
        List<ConditionRelation> andRelations = groupedRelations.get("AND");
        if (andRelations != null && !andRelations.isEmpty()) {
            boolean allMatch = andRelations.stream()
                .allMatch(rel -> checkCondition(userId, rel.getConditionSerialNo()));
            if (allMatch) return true;
        }
        
        // OR规则：任一条件满足即可
        List<ConditionRelation> orRelations = groupedRelations.get("OR");
        if (orRelations != null && !orRelations.isEmpty()) {
            boolean anyMatch = orRelations.stream()
                .anyMatch(rel -> checkCondition(userId, rel.getConditionSerialNo()));
            if (anyMatch) return true;
        }
        
        return false;
    }
    
    /**
     * 检查单个条件
     */
    private boolean checkCondition(String userId, String conditionSerialNo) {
        Condition condition = getCondition(conditionSerialNo);
        
        // 根据条件类型获取用户数据
        BigDecimal actualValue = getUserDimensionValue(userId, condition);
        
        // 根据操作符比较
        return compareValue(actualValue, condition.getOperator(), condition.getValue());
    }
}
```

### 6.2 Web3资产查询

```java
public class Web3AssetService {
    
    /**
     * 查询用户资产余额
     */
    public BigDecimal getAssetBalance(String walletAddress, Condition condition) {
        String protocol = condition.getTypeProtocol();
        String contractAddress = condition.getTypeNo();
        Integer chainId = condition.getChainId();
        
        switch (protocol) {
            case "ERC20":
                return getERC20Balance(walletAddress, contractAddress, chainId);
            
            case "ERC721":
                return getERC721Balance(walletAddress, contractAddress, chainId);
            
            case "ERC1155":
                String tokenId = condition.getTypeTokenId();
                return getERC1155Balance(walletAddress, contractAddress, tokenId, chainId);
            
            default:
                throw new IllegalArgumentException("Unsupported protocol: " + protocol);
        }
    }
    
    /**
     * 查询ERC20余额
     */
    private BigDecimal getERC20Balance(String wallet, String contract, Integer chainId) {
        // 调用区块链RPC或第三方API
        // 例如：Infura, Alchemy, Moralis等
        Web3j web3 = getWeb3Client(chainId);
        ERC20 token = ERC20.load(contract, web3, credentials, gasProvider);
        BigInteger balance = token.balanceOf(wallet).send();
        return new BigDecimal(balance);
    }
}
```

### 6.3 定时任务

```java
@Component
public class GradeAutoCheckTask {
    
    /**
     * 每小时执行一次自动检查
     */
    @Scheduled(cron = "0 0 * * * ?")
    public void autoCheckGrades() {
        // 1. 查询需要检查的用户
        List<UserGrade> needCheckUsers = userGradeMapper.selectList(
            new QueryWrapper<UserGrade>()
                .le("next_check_time", new Date())
                .eq("del_flag", 0)
        );
        
        log.info("自动检查任务开始，待检查用户数：{}", needCheckUsers.size());
        
        // 2. 批量处理
        for (UserGrade userGrade : needCheckUsers) {
            try {
                // 执行等级评估
                GradeEvaluationResult result = gradeEvaluationEngine.evaluate(
                    userGrade.getBizRoleTypeNo(), 
                    userGrade.getBizRoleType()
                );
                
                // 如果需要晋升
                if (result.isNeedUpgrade()) {
                    gradeService.upgrade(userGrade, result.getTargetGrade());
                }
                
                // 更新下次检查时间
                userGrade.setNextCheckTime(calculateNextCheckTime());
                userGradeMapper.updateById(userGrade);
                
            } catch (Exception e) {
                log.error("用户等级检查失败：{}", userGrade.getBizRoleTypeNo(), e);
            }
        }
        
        log.info("自动检查任务完成");
    }
    
    /**
     * 计算下次检查时间（24小时后）
     */
    private Date calculateNextCheckTime() {
        return DateUtils.addHours(new Date(), 24);
    }
}
```

## 九、安全方案

### 9.1 权限控制

- 等级配置：仅管理员可操作
- 规则配置：需要审批流程
- 手动调整：记录操作人和原因
- API访问：JWT Token认证

### 9.2 数据安全

- 敏感字段加密存储（钱包地址）
- 操作日志完整记录
- 数据库定期备份
- 防止SQL注入攻击

### 9.3 业务安全

- 防止恶意刷等级
- 限制手动调整频率

### 12.2 常见问题

**Q1：用户同时满足多个等级条件怎么办？**
A：系统会自动晋升到满足条件的最高等级（grade_num最大的等级）。

**Q2：如何处理等级降级？**
A：在规则配置中开启auto_downgrade，系统会定期检查，不满足条件则自动降级。

**Q3：支持等级有效期吗？**
A：支持，在crm_biz_role_grade表中设置expire_time字段。

**Q4：如何防止用户刷等级？**
A：可以在条件中增加时间维度限制，如"近30天消费>=1000元"。
